The first release of Crontinental: run a command later, once or on a repeat,
and every job checks out.

```
curl -fsSL https://raw.githubusercontent.com/Techneosis/the-crontinental/main/install.sh | bash
```

**Linux** (systemd user timer, a transient unit per run, the journal) and
**macOS** (a LaunchAgent, a session and process group per run, a log file per
job), amd64 and arm64. One static binary; nothing else to install.

- **Every job ends.** A one-off ends when it fires. A repeat must say how:
  `--until <time>`, `--until-done` (the command exits 99 when its work is
  done), or `--forever`. Finished jobs leave `list` at once and are cleared
  three days later.
- **systemd's calendar grammar** (`Mon..Fri 07:30`, `*-*-01 09:00`, `hourly`)
  and intervals (`30m`), read natively and held to `systemd-analyze` on a
  hundred thousand specs across time zones and daylight-saving changes.
  `crontinental check "<spec>"` says when one fires.
- **Times as people type them** for `at` and `--until`: `tomorrow 7am`,
  `next friday 18:00`, `3 days`, `Oct 24 10:00`.
- **Durable**: bookings live in a SQLite ledger, so a reboot loses nothing.
  A missed run while the machine slept is run late or skipped, per job
  (`--catchup`).
- **Safe by construction**: a job can't overlap itself, every run has a
  timeout, failures notify you, and `edit` changes a job without losing its
  history.
- **For AI agents**: every booking records the Claude Code session that made
  it, and the installer can brief Claude Code (a skill, plus a short
  CLAUDE.md section) so agents book here rather than somewhere that won't last.

See the [README](https://github.com/Techneosis/the-crontinental#readme) for the
house rules.
