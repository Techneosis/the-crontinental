Tags: a job can tell its notify hooks where it belongs.

```
curl -fsSL https://raw.githubusercontent.com/Techneosis/the-crontinental/main/install.sh | bash
```

Running the one-liner again upgrades. The ledger moves to schema v3, which only
adds a column: existing jobs carry on as they were, with no tags.

- **`--tag key=value`.** Any booking can carry tags, as many as it likes, and
  `edit --tag` / `edit --no-tag key` change them. Every hook hears them with
  every event about the job, as `CRONTINENTAL_TAG_<KEY>` and as a `tags`
  object in the JSON, so one hook can send the backup's failures to a pager
  and everything else to the desktop. Crontinental gives tags no meaning; your
  hooks do. `show` and `list --json` include them.
- **Messages carry them too.** `crontinental notify` from inside a job goes out
  with the job's tags, and a `--tag` on the message adds to them for that
  message only.
- **The ntfy example** sends a job booked with `--tag ntfy_topic=<topic>` to
  that topic. An installed copy is yours and isn't changed; copy the example
  again to pick this up.
- A tags-only `edit` from an agent isn't refused by the session guard, like
  `--note` and `--notify`.
