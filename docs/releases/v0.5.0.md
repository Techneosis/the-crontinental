One run at a time: per-run logs, and JSON a dashboard can read.

```
curl -fsSL https://raw.githubusercontent.com/Techneosis/the-crontinental/main/install.sh | bash
```

Running the one-liner again upgrades. No schema change.

- **`log <name> --run <id>`** prints what that one run printed, start to
  finish, instead of the job's whole log. On Linux it reads the journal
  between the run's start and end (never into the runs either side); on macOS
  each run's banner in the job's log now carries its id, and runs logged
  before this release are found by their start time. The ledger keeps whole
  seconds, so two runs of a job that start within the same second can share a
  line at their edge.
- **`show <name> --json`** gives the job as `list --json` does, plus its last
  20 runs (newest first) as `runs`, each with its id, times, exit status,
  outcome and lateness.
- **`list --json`** gives every job its latest run as `last_run` (`null`
  before the first), so a dashboard can show health without a `show` per
  job. The existing keys are unchanged.
- Bash completion knows `show --json` and `log --run`.
