The message book, and two daylight-saving fixes.

```
curl -fsSL https://raw.githubusercontent.com/Techneosis/the-crontinental/main/install.sh | bash
```

Running the one-liner again upgrades. The ledger moves to schema v4, which only
adds a table: existing jobs and runs are untouched.

- **The message book.** Every notification, from a job's outcome or from
  `crontinental notify`, is written in the ledger before the hooks hear it,
  hooks or none, so a message nobody saw is never lost. **`messages`** reads
  it back, newest first (`-n N`, default 20; `--json` for a device that wants
  to show them). The book keeps 30 days.
- Hooks get two new variables: `CRONTINENTAL_MESSAGE`, the message's number in
  the book, so whatever showed it can be matched to the record later; and
  `CRONTINENTAL_RUN`, the run it is about or was sent from. The JSON on stdin
  carries the same as `id` and `run`.
- **Fixed: the repeated autumn hour.** In the second pass of the hour that
  repeats when clocks go back, a time taken from now resolved to the first
  pass, an hour earlier. `at now` was refused as being in the past, and
  `at "2 hours"` came an hour early. Such a time now stays on now's side of
  the change.
- **Fixed: the skipped spring hour.** A calendar step with no time of day that
  landed in the hour skipped when clocks go forward went back an hour instead
  of moving past the gap. It now moves past by the size of the gap.
- The comparison against GNU `date` now pins its clock and runs every phrase
  on both sides of each change, so DST is tested on every run rather than only
  near a change.
- Bash completion knows `messages`.
