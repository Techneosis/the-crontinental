Upgrade from the Front Desk.

```
curl -fsSL https://raw.githubusercontent.com/Techneosis/the-crontinental/main/install.sh | bash
```

Running the one-liner again upgrades, one last time: from this release on,
`crontinental upgrade` does it. No schema change.

- **`upgrade`** installs the latest release. It runs the installer that came
  with the release you have, the same way the one-liner does, so the download,
  the SHA-256 check and the swap are the installer's as before. A build from a
  checkout is refused (pull and re-run `./install.sh` there).
- **`upgrade --check`** only asks. It exits 0 when there is nothing newer, 3
  when there is, and 1 when it couldn't find out, so a booking can watch for
  you and ring your notify hooks when a release is out:

  ```
  crontinental every weekly --name upgrade-check --forever -- crontinental upgrade --check
  ```
- Each release now publishes a `VERSION` file beside its archives, which is
  what `upgrade` reads. It honours `CRONTINENTAL_RELEASES`, as the installer
  does.
- Bash completion knows `upgrade`.
