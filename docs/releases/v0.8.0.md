A run knows its own schedule.

```
crontinental upgrade
```

(or the one-liner, from v0.6.0 and before). No schema change.

- **`CRONTINENTAL_NEXT` and `CRONTINENTAL_UNTIL`.** A job's command now gets,
  beside `CRONTINENTAL_JOB` and `CRONTINENTAL_RUN`, when the job is next due
  (the tick has already moved it on) and when its schedule ends, as ISO-8601
  UTC. A job that reports somewhere can say when its next report is due
  without stating its schedule twice:

  ```
  crontinental every 30m --name watch --until "8 hours" -- \
    'check-things && post "all clear; next check ${CRONTINENTAL_NEXT:-never}"'
  ```

  `CRONTINENTAL_NEXT` is unset when the job won't come round again (a one-off,
  a finished repeat, a disabled job run by hand); `CRONTINENTAL_UNTIL` is unset
  without a deadline. Neither is inherited from a run that started this one.
